# Simulation replication

This folder reproduces the dynamic factor model simulations in the paper. It contains the fixed calibration, simulation and estimator code, cluster wrappers, and the 500 CSV files generated by the original simulation runs. The archived output allows the reported figures and tables to be regenerated without rerunning the Monte Carlo experiments.

## Reproducing the paper output

No external data are required. Run the following command from the `simulations/` directory:

```bash
Rscript run_analysis.R
```

The script checks the required analysis packages, reads the archived CSV files, and regenerates the simulation figures and tables. It does not rerun the simulations. A verification run of this output-generation step took approximately 34 seconds on an Apple silicon laptop.

## Inputs and provenance

`dfm_calibration.mat` is the fixed calibration used in every replication. It was created from the baseline DFM workflow in `simulations/main_dfm.m` in the replication files of Montiel Olea, Plagborg-Møller, Qian, and Wolf. The precise source is repository [`ckwolf92/lp_var_nberma`](https://github.com/ckwolf92/lp_var_nberma), [commit `b3315b97540f003005180b13fa78da4fc84a8b39`](https://github.com/ckwolf92/lp_var_nberma/tree/b3315b97540f003005180b13fa78da4fc84a8b39), dated 22 May 2025. After that script constructed `DF_model` and `settings`, the objects were saved without modification using:

```matlab
save('dfm_calibration.mat', 'DF_model', 'settings', '-v6');
```

The object contains the state-space matrices, structural-shock weight, target impulse response, and restricted information set. It uses first-differenced data, six dynamic factors, two factor lags, and two idiosyncratic autoregressive lags.

The simulation code reads `dfm_calibration.mat`. The two calibration CSV files are included for reference and are not used as inputs to the simulation code. `dfm_calibration.csv` stores every scalar, vector, matrix, and nested setting in long form, while `dfm_calibration_manifest.csv` records the corresponding paths, storage types, and dimensions. Regenerate and verify both copies by running:

```bash
Rscript analysis/export_calibration_csv.R
```

As a cross-check, the stored matrices, shock direction, and impulse responses are numerically identical to specification 6, the first-difference robustness calibration, in repository [`dake-li/lp_var_simul`](https://github.com/dake-li/lp_var_simul), [commit `fe78bd362e0ea53b6df57bfe65f7c1aa14ebce04`](https://github.com/dake-li/lp_var_simul/tree/fe78bd362e0ea53b6df57bfe65f7c1aa14ebce04), dated 28 September 2023. This is not their headline levels specification. The calibration and restricted information set were fixed before the Monte Carlo comparisons and were not selected using the results in this package.

## Specification and implementation

All designs use a calibrated DFM with 207 observables and six factors. The response is series 121. The restricted information set consists of columns 121, 56, 151, 193, and 142. Each replication retains 200 observations after a burn-in of 100 and reports horizons 1–12. There are 1,000 replications per design, divided among 50 array tasks of 20 replications.

The common lag order is four. AIC-BC searches lag orders 1–20. OGA uses the ordering and HDAIC criterion in `Ohit` 1.0.0 with `C*=2`. OGA standard errors use a Parzen HAC estimator with four truncation lags.

FAVAR uses 100 bootstrap draws. RSLP averages 1,000 random subspaces, each containing 50 standardized first-lag candidate predictors; the essential variables enter every regression with all four lags. RSLP uses 100 aggregate bootstrap draws. The archived LAVA results are point estimates. The OGA robustness exercise uses `C*` values 1.6, 1.8, 2.0, 2.2, and 2.4.

The three designs are:

- **Shock contamination:** the structural shock is augmented by the first lag of a standardized full-panel index with weights `j^(-1.5)`. The weights are not renormalized and the contamination multiplier is one.
- **Outcome nuisance:** twenty observed AR(1) coordinates with coefficient 0.85 are sample-orthogonalized to the structural shock and standardized. Their normalized loadings are proportional to `j^(-1.5)`, and the nuisance component enters the outcome with coefficient one.
- **Factor contamination:** the structural shock is augmented by twice the standardized first lag of the factor direction in the null space of the restricted loading matrix. Its sign is fixed deterministically.

For task `j` and within-task replication `r`, the DFM seed is `10000 + 1000*j + r`. Separate fixed offsets are used for the nuisance coordinates and randomized estimators. Every output row records the design, task, replication, horizon, method, true response, tuning values, and elapsed time. OGA rows also record selected-variable counts and identities.

## Rerunning the full Monte Carlo analysis

The full simulation consists of ten groups of 50 independent tasks: three method batches for each of the three main designs and one group for the `C*` robustness exercise. This gives 500 tasks in total. Each task runs 20 Monte Carlo replications. The three method batches for a given design use the same replication seeds, so each main design contains 1,000 distinct Monte Carlo replications rather than 3,000.

The complete experiment represents approximately 615 CPU-hours. The launchers do not change the statistical code, task definitions, or seeds; they only determine how the 500 calls to `cluster/run_array_task.sh` are scheduled. Preview a plan before starting either execution route.

### Running without SGE

On a workstation, laptop, or cluster without SGE, use the portable launcher from the `simulations/` directory. It requires Bash, `Rscript`, and an `xargs` implementation supporting `-P`, as supplied by standard macOS and Linux installations.

Preview all 500 tasks without starting them:

```bash
bash run_simulations_local.sh --plan
```

Run the tasks sequentially, which is the safest default:

```bash
bash run_simulations_local.sh --all --jobs 1
```

The `--jobs` option replaces the scheduler concurrency limit. For example, the following command permits at most four independent R tasks to run simultaneously:

```bash
bash run_simulations_local.sh --all --jobs 4
```

Choose this value according to the available processors and memory. Each task was designed for one CPU core, and the LAVA batch is the most computationally demanding. The default is one concurrent task so that running the launcher without an explicit resource choice does not overload a local machine.

To run only part of the experiment, specify a design and optionally a method batch:

```bash
bash run_simulations_local.sh --run --design shock --batch core --jobs 4
bash run_simulations_local.sh --run --design factor --jobs 2
bash run_simulations_local.sh --run --design cstar --batch oga --jobs 1
```

The available main designs are `factor`, `outcome`, and `shock`; their method batches are `core`, `bootstrap`, and `lava`. The `cstar` design accepts only the `oga` batch. Task output is written to `results/simulation/`, and task-specific console logs are written to `logs/local_DESIGN_BATCH_jobNNN.log`. If a task fails, the launcher exits with an error and retains the completed output and logs for diagnosis. Windows users may run this route through WSL or another Bash environment with `Rscript` and `xargs -P` available.

### Running with SGE on CRC

The supplied SGE launcher records the setup used for the original CRC runs. Preview the complete submission plan with:

```bash
bash cluster/submit_simulations.sh --plan
```

Preview mode reports the selected arrays, task count, and concurrency limit and does not submit jobs. Calling the launcher without an action also does not submit jobs; it prints the usage instructions.

After reviewing the plan, explicitly submit the full simulation with:

```bash
bash cluster/submit_simulations.sh --all
```

The default limit is 10 simultaneously running tasks within each array. It can be changed explicitly, for example:

```bash
bash cluster/submit_simulations.sh --all --max-concurrent 5
```

To submit only part of the experiment, specify a design and optionally a method batch:

```bash
bash cluster/submit_simulations.sh --submit --design shock --batch core
bash cluster/submit_simulations.sh --submit --design factor
bash cluster/submit_simulations.sh --submit --design cstar --batch oga
```

The launcher prints every SGE job identifier after submission. The following settings are specific to the University of Notre Dame CRC environment and may be adapted for another SGE installation:

- the `qsub` command and SGE array syntax;
- queue name `long`;
- parallel environment request `-pe smp 1`;
- array range `-t 1-50` and concurrency option `-tc`;
- R module command `module load R/4.5.2/gcc/11.5.0`;
- SGE variables such as `SGE_TASK_ID` and scheduler log routing.

These settings appear only in `cluster/submit_simulations.sh` and `cluster/sge_array_job.sh`. The R jobs and `cluster/run_array_task.sh` do not depend on SGE or CRC paths.

### Shared task wrapper and final output

For testing or for running one task directly, the portable wrapper takes a design, method batch, and task ID:

```bash
bash cluster/run_array_task.sh factor core 1
bash cluster/run_array_task.sh outcome bootstrap 1
bash cluster/run_array_task.sh shock lava 1
bash cluster/run_array_task.sh cstar oga 1
```

Task IDs run from 1 through 50. Simulation settings are defined in `R/configuration.R` and `cluster/run_array_task.sh`. Both launchers call this same wrapper, so the execution route does not alter the task seeds or specifications.

Once all requested tasks have completed under either route, regenerate the figures and tables from the new output by running:

```bash
Rscript run_analysis.R
```

The complete loaded dependency environment, including transitive packages, is recorded in `logs/crc_session_info.txt`. The installer pins the packages in the table; it does not claim to reconstruct an unrecorded lockfile for every transitive dependency.

From the `simulations/` directory, inspect the installation plan without changing the R library:

```bash
Rscript install_packages.R --list --profile crc
```

Under R 4.5.2, install and then check the recorded package versions with:

```bash
Rscript install_packages.R --profile crc
Rscript install_packages.R --check --profile crc
```

Exact archived versions may be installed from source and therefore require standard R compilation tools. The `MASS` version is the recommended-package version distributed with the recorded R installation. No MATLAB installation is required; `R.matlab` reads the included version-6 MAT file directly.

The simulations were run as 50-task arrays on the CRC cluster using the SGE `long` queue and one CPU core per task. The runs used R 4.5.2 compiled with GCC 11.5.0.

The recorded CRC session reports Red Hat Enterprise Linux 9.7, BLAS and LAPACK supplied with R 4.5.2, and the complete loaded package versions. See:

```text
logs/crc_session_info.txt
```

The archived files contain elapsed-time records for every replication. Summing those records gives approximately 615 CPU-hours for all simulations in this package. Under the original allocation of 50 concurrently running one-core tasks per array, with the method batches run successively, the recorded task durations imply approximately 4.0 hours for the shock-contamination design, 4.1 hours for the factor-contamination design, and 5.6 hours for the outcome-nuisance design. The C* robustness array required less than one minute under the same allocation. These figures exclude scheduler queueing time, which was not recorded. Most of the computational cost is attributable to LAVA.

Table S3 reports median wall-clock times calculated from the elapsed-time fields recorded during the original simulation runs. These values describe that computing environment and may differ across processors, available memory, R and package versions, concurrent-task allocations, and system load.
